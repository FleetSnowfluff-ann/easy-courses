💎什么是 Obsidian？

入门基础 了解 Obsidian 的核心理念与适用场景

Obsidian 是一款基于本地 Markdown 文件的知识管理与笔记工具。它的核心哲学是：你的笔记是永久属于你的——所有数据以纯文本格式存储在本地，不依赖任何云服务，保证数据主权。

「Obsidian 就是你思想的第二大脑——一个让知识自由流动、相互连接的数字花园。」

Obsidian 的五大特色

🗂️
本地优先
所有笔记存为 .md 文件，永久可读，不锁定在任何平台
🕸️
双向链接
用 [[链接]] 语法连接笔记，形成知识网络
🔭
图谱视图
可视化你的整个知识库，发现隐藏连接
🔌
丰富插件
1000+ 社区插件，按需扩展任意功能
⚡
速度极快
基于 Electron 构建，打开即用，无加载等待
🆓
免费使用
个人使用完全免费，付费功能仅为可选增值服务

创建你的第一个 Vault（知识库）

Vault（保险库/知识库）是 Obsidian 的核心概念——本质上就是一个普通的文件夹，Obsidian 将它作为笔记的根目录。

1
启动 Obsidian，点击「Create new vault」
首次启动会出现欢迎界面，选择「新建知识库」选项
2
为 Vault 命名，选择存储位置
推荐放在 ~/Documents/MyVault 或 iCloud/OneDrive 下以便多设备同步。名称建议简短有意义，如「学习笔记」「工作知识库」
3
进入界面，熟悉四大区域
左侧文件树、中间编辑区、右侧面板（反向链接等）、底部状态栏
4
打开设置（⌘, / Ctrl+,），做基础配置
建议首先设置语言为中文、调整字体大小、开启「默认文件夹」等

🔗双向链接系统

进阶功能 Obsidian 最核心的知识连接机制

双向链接是 Obsidian 的灵魂功能。当你在笔记 A 中写 [[笔记B]]，Obsidian 不仅会在 A 中显示指向 B 的链接，还会在 B 的「反向链接」面板中自动显示「A 链接了我」——无需手动维护，知识之间的网络自动形成。

链接语法详解

# 基础链接
[[机器学习]]                    # 链接到「机器学习」笔记
[[机器学习|ML 概述]]            # 显示为「ML 概述」，但链接到「机器学习」
[[机器学习#监督学习]]           # 链接到「机器学习」笔记的「监督学习」章节
[[机器学习#监督学习|点我跳转]]  # 章节链接 + 自定义别名

# 嵌入（内联展示其他笔记）
![[机器学习]]                   # 将整篇「机器学习」笔记嵌入到当前位置
![[机器学习#简介]]              # 只嵌入「简介」章节
![[图表.png|400]]              # 嵌入图片并设置宽度为 400px

# 外部链接（标准 Markdown）
[Obsidian 官网](https://obsidian.md)

反向链接（Backlinks）

这是双向链接系统的核心体验。打开右侧面板中的「反向链接」视图，就能看到所有链接到当前笔记的笔记列表。

图：三篇笔记链接到「机器学习」，其反向链接面板自动显示所有来源

未解析链接（Unresolved Links）

Obsidian 允许你先写下 [[尚不存在的笔记名]]，这个链接会以虚线显示。当你将来创建这篇笔记时，链接自动激活。这种「先占位、后填充」的工作方式大幅降低了写作时的阻力。

链接提示与自动补全

1
输入 [[，自动弹出搜索面板
开始输入笔记名的任意部分，Obsidian 会实时模糊搜索所有笔记标题
2
用 ↑↓ 键选择，Enter 确认
也可以用鼠标点击候选项
3
按 | 键可立即为链接添加别名
例：[[机器学习|ML]] — 在当前笔记显示为「ML」但实际链接到「机器学习」
🔗 最佳实践：链接时多用别名
在自然语言段落中使用链接时，借助别名保持文字流畅。例如：「[[机器学习|这门技术]]改变了世界」比「[[机器学习]]改变了世界」读起来更自然。

🏷️标签与文件夹

进阶功能 用标签实现跨文件夹的灵活分类

标签（Tags）与文件夹各有侧重：文件夹负责物理存储结构，标签则实现跨结构的多维分类。一篇笔记只能在一个文件夹里，但可以贴无数个标签。

标签使用方式

# 方式 1：正文中直接添加（推荐）
这是关于神经网络的学习笔记 #AI #深度学习 #进行中

# 方式 2：通过 Front Matter 添加（可被 Dataview 查询）
---
tags:
  - AI
  - 深度学习
  - 进行中
---

# 嵌套标签（创建层级）
#学习/机器学习
#学习/深度学习
#状态/草稿
#状态/完成

标签面板与搜索

在左侧面板点击「标签」图标，可以看到所有标签及其使用数量。点击任意标签，会在搜索框中自动填入 tag:#标签名 并显示所有包含该标签的笔记。

在搜索框中也可以使用高级标签搜索：

tag:#AI所有含 #AI 标签的笔记
tag:#学习/机器学习含嵌套标签的笔记
tag:#AI tag:#进行中同时含两个标签（AND 关系）

链接 vs 标签 vs 文件夹：如何选择？

📁
文件夹：用于物理分类
项目、领域等有明确归属的笔记。层级不宜超过 3 层
🏷️
标签：用于状态与属性
笔记状态（#草稿 #完成）、类型（#概念 #教程）、话题（#AI #读书）
🔗
链接：用于语义关联
有内容关联的笔记之间。「机器学习依赖[[线性代数]]」这种有意义的连接
💡 推荐的标签体系
建立一套简洁一致的标签系统，例如：
• #状态/草稿 #状态/完成 #状态/归档
• #类型/概念 #类型/项目 #类型/日记
• #话题/AI #话题/编程 #话题/读书

🔭图谱视图

进阶功能 可视化你的整个知识库，发现知识结构

图谱视图（Graph View）将每篇笔记渲染为一个节点，笔记之间的链接渲染为边，形成一张可交互的知识地图。笔记越多被链接，节点越大。

图谱演示

图：图谱视图中，节点大小代表被链接的次数

图谱视图的使用技巧

1
打开图谱视图：左侧 Ribbon 点击图谱图标，或使用命令面板
快捷键：Ctrl+G（Windows）或 ⌘G（Mac）
2
在右上角过滤器中按标签/文件夹筛选
通过 tag:#AI 只显示 AI 相关笔记的子图，避免全局图过于密集
3
调整「局部图谱」深度
在单篇笔记的右侧面板可开启「局部图谱」，只展示该笔记周围 1-3 跳的节点
4
通过颜色区分群组
在图谱设置中，可以按照路径、标签等条件为不同类型的节点设置颜色
⚠️ 避免误区
图谱视图最大的价值不是「好看」，而是发现孤立笔记——那些没有任何链接的孤点，往往是被遗忘的宝贵内容。定期看一看图谱，找出孤点并尝试将它们与其他笔记连接起来。

📋模板系统

进阶功能 通过模板实现标准化笔记结构

模板（Templates）让你在创建新笔记时，一键填入预设的结构和内容，避免重复劳动。Obsidian 内置模板功能，社区插件 Templater 提供了更强大的能力。

启用内置模板插件

1
设置 → 核心插件 → 开启「模板」
Obsidian 的模板功能是核心插件，默认可能未开启
2
在「模板」插件设置中，指定模板文件夹
建议新建一个 Templates/ 文件夹，将所有模板文件放入其中
3
创建新笔记后，命令面板（Ctrl+P）搜索「插入模板」
也可以为「插入模板」命令自定义一个快捷键，如 Ctrl+T

🗃️Dataview：把笔记当数据库

高级功能 用 DQL 查询语言动态生成笔记视图

Dataview 插件让你用类 SQL 语言查询所有笔记的元数据，动态生成表格和列表。知识库越大，Dataview 越有价值。

Dataview 基础语法

在笔记中创建一个代码块，语言类型写 dataview，即可执行查询：

```dataview
# 示例 1：列出所有标签含 #AI 的笔记
LIST
FROM #AI
SORT file.ctime DESC

```
```dataview
# 示例 2：显示所有读书笔记的表格
TABLE 书名, 作者, 评分, 阅读日期
FROM "03-Resources/读书笔记"
WHERE status = "finished"
SORT 阅读日期 DESC
```
```dataview
# 示例 3：显示本周未完成的任务
TASK
FROM "01-Projects"
WHERE !completed
SORT file.mtime DESC
```
```dataview
# 示例 4：最近 7 天修改的笔记
LIST file.mtime
FROM ""
WHERE date(today) - file.mtime <= dur(7 days)
SORT file.mtime DESC
```

常用字段参考

字段含义
file.name笔记文件名（不含扩展名）
file.path笔记的完整路径
file.ctime创建时间
file.mtime最后修改时间
file.tags笔记所有标签
file.inlinks所有指向此笔记的链接
file.outlinks此笔记指向的所有链接
任意 Front Matter key如 status、评分

实用查询：构建「每日回顾」页

# 每日回顾 Dashboard

## 今日创建的笔记
```dataview
LIST
FROM ""
WHERE file.ctime >= date(today)
```

## 进行中的项目
```dataview
TABLE status, file.mtime AS "最后更新"
FROM "01-Projects"
WHERE status != "archived"
```

## 最近读完的书
```dataview
TABLE 书名, 评分
FROM #读书笔记
WHERE status = "finished"
SORT 阅读日期 DESC
LIMIT 5
```
💡 Dataview 使用前提
Dataview 依赖 Front Matter 中的元数据。笔记元数据越丰富（日期、状态、标签、评分等），能执行的查询就越强大。从现在开始养成填写 Front Matter 的习惯！

🚀工作流与最佳实践

高级应用 把零散功能整合为高效的日常工作流

推荐工作流：CAPTURE → ORGANIZE → REVIEW

日常使用清单

⏰ 每日（5 分钟）

  • 用模板创建今天的每日笔记
  • 快速记录当天要做的事、学到的内容
  • 遇到关键词时，随手加上 [[链接]]

📆 每周（30 分钟）

  • 清空 Inbox——将笔记归类或删除
  • 检查未解析链接，为孤立笔记建立连接
  • 打开图谱视图，寻找知识空白区
  • 更新项目笔记的进展状态

🗓️ 每月（1 小时）

  • 归档已完成的项目到 Archive 文件夹
  • 回顾该月的每日笔记，提炼关键洞见
  • 更新 README/Dashboard 笔记

新手常见误区

误区正确做法
过度设计文件夹结构，纠结分类先放 Inbox，后整理；结构跟随需求成长
笔记太短（每条一两句），没有语境笔记要「原子化」但有自含义，最少一段话
链接用太少，知识孤立写完每篇笔记后，问「这和哪几篇笔记有关？」
安装太多插件，反而分心先精通核心功能，再按需添加 1-2 个插件
追求「完美系统」，迟迟不开始今天就建 Vault，开始写第一篇笔记
